Build a working MVP web application called **SurgeAir AI**.

SurgeAir AI is an AI-powered omnichannel airline passenger assistant being developed for an AWS Communication Developer Services (CDS) hackathon.

## Core Demo Scenario

The demo passenger is:

**Passenger:** Draymond Hillsend
**Booking Reference:** SG4821
**Route:** Lisbon (LIS) → Edinburgh (EDI)
**Original Flight:** SA204
**Flight Status:** Delayed by 3 hours

Draymond receives a notification from SurgeAir AI informing him about the delay.

Draymond replies:

“I need to arrive in Edinburgh before 6 PM.”

SurgeAir AI should understand his request, retrieve his booking, search for suitable alternative flights, present the available options, allow him to select an alternative, explicitly request confirmation, and only then perform the simulated rebooking.

## Required Backend Functions

Create a clean API-based backend with these operations:

### getBooking

Accept a booking reference and return the passenger's booking.

For SG4821 return:

Passenger: Draymond Hillsend
Flight: SA204
Origin: LIS
Destination: EDI

### getFlightStatus

Accept a flight number and return its current status.

SA204 should return:

Status: Delayed
Delay: 3 hours

### searchAlternativeFlights

Accept:

* Origin
* Destination
* Arrival-time constraint

When Draymond asks to arrive before 18:00, return SA218 and SA226.

### rebookFlight

Accept:

* Booking reference
* Selected flight
* Passenger confirmation

IMPORTANT:

Never modify the booking until Draymond explicitly confirms the change.

For example:

Draymond:
“Book SA218.”

SurgeAir AI must respond with a confirmation request such as:

“SA218 arrives in Edinburgh at 14:40. Would you like me to rebook SG4821 from SA204 to SA218?”

Only after Draymond responds with something equivalent to:

“Yes, confirm.”

should `rebookFlight` execute.

After successful rebooking:

SG4821
Old flight: SA204
New flight: SA218

### sendItinerary

Generate an updated itinerary after successful rebooking.

For Milestone 1, simulate email delivery.

Design this function so Amazon SES can replace the simulated implementation later.
