Build the first working MVP of an application called **SurgeAir AI**.

SurgeAir AI is an AI-powered omnichannel airline passenger assistant being developed for an AWS Communication Developer Services hackathon.

## Core Demo Scenario

A passenger is travelling:

**Lisbon (LIS) → Edinburgh (EDI)**

Passenger:

* Name: Alex Morgan
* Booking reference: SG4821
* Original flight: SA204

Flight SA204 has been delayed by 3 hours.

The passenger tells SurgeAir AI:

“I need to arrive in Edinburgh before 6 PM.”

SurgeAir AI should retrieve the passenger's booking, understand the arrival-time constraint, search available alternative flights, present suitable options, ask the passenger to confirm their choice, and only then perform the simulated rebooking.

## Backend

Create a clean API-based backend that can later be migrated to AWS Lambda and Amazon API Gateway.

Implement these operations:

1. `getBooking`

   * Accept booking reference.
   * Return passenger and booking information.

2. `getFlightStatus`

   * Accept flight number.
   * Return flight status and disruption information.

3. `searchAlternativeFlights`

   * Accept origin, destination and passenger constraints.
   * Search the mock flight inventory.
   * Support an arrival-before constraint.

4. `rebookFlight`

   * Accept booking reference and new flight.
   * DO NOT change a booking unless explicit passenger confirmation has been received.
   * Update the mock booking after confirmation.

5. `sendItinerary`

   * For Milestone 1, simulate sending an itinerary.
   * Structure this function so Amazon SES can replace the simulation later.

## Conversation State

Maintain a conversation object containing:

* passenger ID
* booking reference
* current flight
* origin
* destination
* current communication channel
* previous communication channel
* passenger request
* detected intent
* constraints
* selected alternative flight
* confirmation status
* action status

The architecture must allow this state to later be stored in Amazon DynamoDB so the same conversation can continue across SMS, WhatsApp, RCS and email.

## Agent Logic

Create an agent layer capable of following:

UNDERSTAND
→ RETRIEVE BOOKING
→ CHECK FLIGHT
→ EXTRACT CONSTRAINT
→ SEARCH ALTERNATIVES
→ PRESENT OPTIONS
→ WAIT FOR PASSENGER SELECTION
→ REQUEST CONFIRMATION
→ WAIT FOR CONFIRMATION
→ REBOOK
→ GENERATE CONFIRMATION
→ SEND ITINERARY

Never perform a rebooking solely from an inferred preference.

Require an explicit confirmation such as:

“Yes, confirm.”

before executing `rebookFlight`.
